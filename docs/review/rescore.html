The short version

Every one of the original 141 findings was worked. The panel's own “what holds” notes read like a checklist of them — verb-aware retry with reconcile-by-name, the job reaper, typed provisioner results, rendered admin alerts, a filterable audit log with CSV export, indexed balance aggregates, real database-level idempotency tests.

But closing them took roughly 8,300 lines of new code, and a fresh panel scores the code in front of it, not the diff. The new surface carried new defects — including two that put wrong money in real customers' ledgers. Three dimensions rose sharply; five fell.

Two things are worth knowing before reading the table. First, these scores are a snapshot taken mid-repair: several judges filed criticals that were already fixed when they filed them, and one critical they found has been fixed since. Second, the single largest drag — no production payment gateway ships — is a pre-existing structural gap this round did not close, and it is what took Product Completeness down 14 points.

Why each direction happened

The reasons are asymmetric: the gains came from the remediation, and so did most of the losses.

What earned the rises

  • Testing +15. The suite went from 46 tests to 178, and — more importantly — from unable to reach a single database path to exercising the real unique keys and optimistic-claim guards through a SQLite-backed $wpdb double. The judge attacked the assertions and the shim and reported they held.
  • Operational readiness +10. The “customer paid, no server” incident is now fully recoverable from wp-admin: payment-reference lookup, order reclaim/retry/refund, full job payload and error, stale-job reap, filterable audit with export, self-updating credential health.
  • Reliability +5. Every concurrency guard the judge attacked — claim, transition, renewal clock advance, job claim, ledger unique key — proved to be a real conditional UPDATE or unique constraint rather than a read-then-write.

What caused the falls

  • Product completeness −14. No production payment gateway ships. With a real ArvanCloud token, checkout and top-up return 503 — and onboarding still declares the shop ready. The first panel flagged this and scored 82 anyway; this one priced it properly.
  • Code quality −10. New config surface that does not work: six option keys readable but permanently unsettable, retention split across two option names, and a brand colour declared in five places under a docblock claiming one source of truth.
  • Scalability −8. Two batch engines capped below the documented envelope, plus a type error that killed the usage-sync resume path outright.
  • Security −6. The perimeter held under direct attack, but two money-path controls that the docs present as enforced turned out not to be wired.

Three defects were caught only by packaging and installing the plugin, not by any amount of code review: a runtime file missing from the archive that made the plugin impossible to license; a compiled translation catalogue whose generator self-verified with a more lenient reader than WordPress uses, so it would have shipped and translated nothing; and a sign inversion that would have suspended every customer with any history on day one.

Why the release is held

The package builds and passes all 123 end-to-end checks. It has not been tagged or published, because the panel proved these first.

B1

The v5 migration back-dates every renewal clock

The backfill set renews_at = created_at + 30 days for every service at upgrade time. A six-month-old service gets a date five months in the past, and the renewal job then bills one back-dated term per run until it catches up — real wallet debits against real customers for periods that were never sold.

B2

Demo services keep billing after go-live

Leaving demo mode does not retire demo inventory, and both writers stamp the demo flag from the ambient request-time mode rather than the originating row. Seeded demo services therefore manufacture real revenue and real customer debt.

B3

The refund settlement guard was never wired

The function that refuses a refund when the original purchase was never ledgered exists, is tested, and has no production caller — the admin button appends to the ledger directly. One payment can yield double the spendable wallet credit.

Shipping a migration that charges customers for periods they never bought is not a defensible way to hit a deadline. A fix pass covering these is in flight; the tag and release are one command away once it lands and the suite is green.
