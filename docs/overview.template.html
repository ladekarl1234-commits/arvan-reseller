What it does

A complete reseller operating system

Three storefronts

Cloud Server, CDN and Object Storage — real plan configuration, created idempotently by the setup wizard, working under any theme.

Pricing engine

Global / per-product / per-customer markup, discounts, fixed adjustments — always server-side, with an immutable pricing snapshot per order.

Replay-safe payments

Provider interface + a working sandbox gateway. Callbacks are verified, amount-bound and idempotent — a duplicate never double-charges or double-provisions.

Instant provisioning

Three-layer idempotency (atomic claim + unique keys) and durable retry jobs. A refresh, replay or retried job can't spawn a second remote resource.

Wallet ledger & usage

Append-only ledger — no mutable balance column. Usage ingests once per period, debits the ledger, and a policy engine stages credit health.

Security as a feature

Encrypted credentials, object-level authz, prepared SQL throughout, nonces, an audit log — plus a threat model and a demo that proves replay-safety live.

Security engineering

Controls with a code address, not a promise

✓

Payment integrity

Price recomputed server-side; callback proof is an HMAC over ref|amount|type; a single atomic UPDATE kills replays and races.

✓

Customer isolation

Every /me/* query is scoped by the session user id — IDs never come from the request. Verified by test.

✓

Secrets at rest

Arvan tokens sealed with libsodium secretbox, keyed from WordPress salts; masked in UI, never in REST or logs.

✓

Provisioning idempotency

Service-row check, state-machine claim, and a UNIQUE(order_id) — three independent layers.

✓

Injection & CSRF

100% $wpdb->prepare(), escape-at-sink templates, a nonce on every state change.

✓

Auditability

Credential, pricing, refund and license events land in an append-only audit log with IP.

Honest by design

What is a real limitation, and its fallback

No public Arvan billing/usage API (verified)

Real-mode per-resource usage can't be fetched. The reseller bills fixed monthly packages; the full usage engine is proven via a boundary-faithful demo provider, with one integration point ready for the day Arvan publishes an API.

No public pricing API

Base costs are an admin-maintained table, seeded from the public pricing page with source and timestamp stamps.

Live paid provisioning not fired from this build

No real Arvan credential was available here. The endpoints, client and error handling are implemented against the verified specs; the connection test exercises real HTTP the moment a token is entered.
